# 验证记录

## 自动化与本地报表

`python -m unittest discover -s tests -v`：20 个通过。覆盖真实 HTTP 请求、租户隔离、只读权限、CSV 异常、指标计算、任务续跑、人工审批和配额。读取器在本地通过 3 份计划导出的表头和行解析检查。仓库使用合成数据。读取成功只代表格式兼容，指标与平台后台逐日对账需要用同日期、同筛选和归因窗口进行。

## 本地压测

命令 `python -m scripts.benchmark`。2026-11-21 在 Windows 单机执行。HTTP 客户端和服务位于同一台机器，SQLite 文件置于临时目录。每账户 28 天、每天 3 条合成计划明细，测试请求读取一天的报表，先用 10 次请求预热。各组请求并发值为线程池上限。

| 并发 | 请求数 | QPS | P50 ms | P95 ms | P99 ms | 错误率 |
|---:|---:|---:|---:|---:|---:|---:|
| 10 | 30 | 683.9 | 13.56 | 16.64 | 18.15 | 0% |
| 50 | 150 | 901.2 | 50.05 | 55.70 | 58.02 | 0% |
| 100 | 300 | 894.4 | 97.94 | 109.44 | 111.95 | 0% |

100 并发吞吐与 50 接近，P95 接近两倍。该结果表明这组本地读请求增加并发后延迟上升。瓶颈归因需要进一步分别测 HTTP 调度、连接建立、数据库查询时间。大规模文件、写入和模型调用有各自的性能特征。

## 单客户月度模型成本示例

以费率输入 ¥2 / 百万、输出 ¥8 / 百万估算。假设一天 10 次普通调用，各 4,000 输入、1,000 输出，单次 ¥0.016。一天 2 次诊断，各 20,000 输入、4,000 输出，单次 ¥0.072。30 天合计 ¥9.12。这里使用假设用量，应用中的真实费用看板用服务商返回的用量和配置的费率，失败且无用量回报时保留预算预留金额。离线演示模型 API 成本为零。

## 真实环境验收

用两个脱敏账户连续 28 天的逐日计划数据逐项对账。问数用 20 个问题评估命中率，检索用预先标注的 SOP 和复盘评估 Top 3，诊断用人工判定的异常环节和建议可执行性评分，按账户记录分母。公网 HTTPS、机器人投递、模型费用和准确率以实际环境验证结果为准。
